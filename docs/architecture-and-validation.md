# Football Focus：架构优化与验证说明

日期：2026-10-02。状态：计算链路、推荐门控及前瞻研究改造；不宣称模型已提高命中率。

## 目标与范围

将网站从“能给出很多预测”推进到“每个预测有可追溯输入、明确目标、可复现验证”。保留全部历史原始快照和既有17:00/21:00批次；不重算历史概率，不补造当时未采集的数据。发布时保持站点当时的访问策略；当前为 public。

本轮依据参考评审核对代码后落地；不改变官方数据访问权限、不绕过上游拦截、不取消用户设定的最低命中盈利约束。线上新证据采用 D1 元数据与 R2 完整内容，旧 JSON 原件保留。

## 计算与数据流

```text
官方赛事/各玩法赔率 + 每家公司自己的欧赔/亚盘/大小球
  → 官方身份匹配 + 输入校验 + 每个销售日独立读取时间
  → modelInput（不可变原始输入）+ modelParameters（冻结参数）
  → predictFromSnapshot（线上和离线共用纯函数）
  → 完整比分分布 → 五种玩法一致的概率
  ├→ 推荐约束与选场目标 → 组合票 → 原样留档 → 官方赛果结算
  └→ 同时点市场基线 → 历史重放与诊断 → 人工审核后才可能晋级
```

| 模块 | 职责及边界 |
| --- | --- |

## 已修正的关键问题

### 1. 盘口与价格保持绑定

过去用sigmoid近似亚洲盘结算，并分别取盘口、价格中位数。现在每家公司使用自己的盘口和水位计算残差，公司残差取平均，避免报价数量改变该市场权重。中位数仅用于描述性展示，不参与构造“并不存在的公司盘口”。

四分之一盘等额拆到相邻半球盘。例如−0.25拆为−0.5与0；大2.25拆为大2与大2.5。对于全比分分布累计赢本金W、输本金L、退回本金P：

```text
W + L + P = 1
单位本金净期望 = 香港净赔率 × W − L
公平香港净赔率 = L / W
与双边去水比较的概率 = W / (W + L)
```

该概率不是普通全赢概率。比例去水仍是建模假设，不等同于客观真实概率。拆注语义参考 [Pinnacle 官方双盘口说明](https://support.pinnacle.bet/hc/en-us/articles/44970964829713-How-do-Double-Handicap-and-Double-Totals-bets-work-and-how-are-they-displayed)。

本轮删除旧经验盘口差惩罚；保留胜平负0.48、亚盘0.30、大小球0.18、合规体彩让球0.38等经验拟合权重，尚未证明其最优。模型升至 `multi-market-poisson-v6-exact-settlement`，不可与旧版本混称为同一模型。

### 2. 缺失、过期与部分失败不再混淆

- 缺失盘口不再等于0球；缺失双边价格不再等于50%/50%。输入不足时不生成概率。
- 每个销售日缓存带自己的 `fetchedAt`，命中旧缓存不会借用另一个销售日的新时刻。
- 一个销售日抓取失败不会让其余成功销售日一起失败；返回 `sourceFailures`，未覆盖比赛保留解释。
- 外围研究赛事仍与官方可执行预测隔离。没有官方身份/有效赔率/资格时，不进入正式固定票。
- `fetchedAt` 表示本站读到响应的时刻，不冒充赔率最后变动时刻；上游未提供后者则保持未知。体彩赔率不新鲜时，不参与模型拟合和市场基线计算。

### 3. 线上、离线计算一致

新快照保存 `modelInput`、`modelParameters`、模型版本、各源读取时间与官方八项总进球赔率。原始输入/参数进入输入哈希。相同输入可用同一个纯函数重放，避免在验证中只重新调节一个概率而遗漏整条推理链路。

温度应用在最终比分的胜/平/负边际上；按组缩放比分后再派生总进球与让球。半全场采用给定全场比分下的半场进球二项拆分，保持其全场边际与胜平负一致。该半场模型仍有独立进球/固定时间占比假设，需要未来验证。

半场进球占比的分子和分母只使用同一组半场/全场均有效的比赛，并记录配对样本数。没有半场数据不再把占比机械压低。模型评估也不再在缺少赛前记录时回退到赛后记录。

### 4. 校准和AI门控

校准温度至少30场独立校准样本，并继续向1收缩。新模型只可能接受基线版本、融合版本、应用阶段、schema及完整重放验证均兼容的profile。旧profile保留为历史诊断，但不套在新模型上。

当前旧概率校准页面输出 `legacy-probability-diagnostic`，其“原始输入重放”晋级门槛固定为未通过，不能自动发布参数。测试集不再决定AI权重；运行入口暂时将AI数值权重固定为0，仍可生成有来源的文字复核及影子候选。不因某次测试集较好就开启融合。

后续只有冻结的候选在未来样本及滚动窗口中通过全部门槛，才允许审核签发。当前没有这样的v6证据，不宣称提升准确率。

### 5. 推荐目标与真实风险分离

新票使用确定性候选搜索与稳健期望收益门控，再按每日预算、单场/联赛暴露、共享场次和重复票约束筛选；这是有界搜索，不是全局最优证明。A/B/C 是不同组合方案，不是独立模型。保存原始选项、投入、注数、未推荐原因和跨场独立假设。

“10倍”“2倍”是命中时的条件净利目标，不是保证收益；达不到目标不推荐。当前正式票也要求正期望余量与概率下调压力检查。手动保存校验原票的玩法、单/双选、场数、允许选项、选项概率合计及最低命中净利，不用其他便宜候选替换原票。`scores` 与 `picks` 双重选项别名被拒绝，防止校验和收益计算使用不同内容。

## 当前研究和自动采集边界

- AI 只整理服务器签名的冻结事实、冲突及缺失；数值权重为 0。同一来源的多个接口不构成独立证据共识。
- 盘口隐含进球不是射门 xG；赔率拟合误差不是预测准确率。完整比分分布的不同玩法投影不是多个模型投票。
- 半全场的新票只作研究；既有真实历史票保持原样结算。倍投为 1、2、3、4…线性递增、中奖后重置的资金情景，不提高单场概率。
- 独立球队候选使用决策前已观测的真实历史；当前数据不足时显示不足，不复制盘口候选伪装成独立模型。
- 冻结前瞻实验目前主指标只覆盖胜平负 HAD；未证明比分、总进球或半全场也有增益。冻结版本、真实采集凭证、首次观测赛果和日期分块不确定性缺一不可；不会自动晋级。
- 本地静态索引和云端运行记录合并展示。云端完整原始内容在 R2，D1 只存内容地址、哈希和查询元数据；来源失败的时段保留未知范围，不能据此声称全部覆盖。
- 云端采集入口、存储与页面读取已在源代码中实现；实际部署、无人值守写入回读和云端任务启用须分别核验，不能由代码存在推断已运行。
- 云端所有写入共享数据库时钟驱动的120秒租约和单调递增代次。不同请求不能并行写入同批证据；有效任务续期，失效任务的原始记录、收据、赛果、索引及任务完成均在SQL内被拒绝。中断恢复只处理更早代次，永不授予严格前瞻资格。
- 17:00/21:00概率对照读取两批全部冻结预测，包括未入选组合及明确不投注批次；只配对相同官方比赛与版本，现金投入、返还及净利另行展示。
- 批次时刻按真实时间转换到北京时间，不直接截取UTC字符串。因采集窗口关闭、停售或资格校验失败而不可执行的云端票仍保留完整概率用于描述性研究，但不进入可执行票或现金统计。延迟/恢复记录一律不进入严格前瞻配对；在允许重试窗口内且仍具真实可售资格的票保留延迟标记及现金记录，不冒充准时批次。
- 21:00试算保存会合并打包历史、最新本地原件及合规云端票，校验17:00已占用的预算；读取失败则拒绝保存，不能用旧索引低估当天投入。
- 桌面与云端正式票都要求全部合规比赛完成评估。只有部分预测就绪时保留失败尝试并允许重试，不能先写一份不完整的不可变正式票挡住后续采集。

最低命中盈利非负 ≠ 无风险 ≠ 长期期望收益为正。所有未命中时可能损失全部本金。不同场次概率相乘仍依赖独立假设；相关风险与概率误差可能使估算过于乐观。历史票未记录的目标显示“历史版本未记录”，不反向补写今天规则。

## 总进球双选的验证口径

官方“总进球数”八项赔率完整时，倒数归一化得到市场基线；固定标签顺序打破并列概率，7球及以上统一进入7+。要求同一官方ID/销售日、决策快照、赛前实际采集时间，赔率读取时刻不晚于决策且不超过5分钟。缺失历史赔率不允许用当前赔率替补。

先比较单场Top2命中率、八分类Brier与Log Loss；组合比较固定同样两场或三场，不允许模型选一组、市场另选一组。双选2串1固定4注8元，双选3串1固定8注16元；返还为实际命中项SP连乘×2元，不中返还0。

```bash
npm run audit:model-replay
```

该命令只读原始快照和已核验结果，不写入、不晋级、不发布。本轮初次检查：385条原始预测记录因缺少新版本原始输入而不可比较，非385场独立比赛；有效可比较场次为0，指标输出null而不是0%或虚构提升。旧复盘仍可显示当时保存的预测和赛果。

## 存储决策与分阶段路线

旧历史的权威原件仍是只追加JSON，紧凑索引只是Site读模型；IndexedDB仅为设备缓存。D1的 `saved_purchase_trials` 按用户隔离手动试算。新的线上采集路径已实现D1查询元数据、不可变R2完整对象及回读哈希校验；生产部署和无人值守能力仍需实际核验。没有迁移或删除旧JSON，云端与本地证据按不可变身份合并。

下一阶段建议按顺序实施：

1. 建立原始输入覆盖率、各来源时效、不可比较原因、快照漏采率的健康看板；区分故障、无赛事和无合规票。
2. 累积v6原始输入与冻结候选，建立完整按时间训练/校准/测试的重放签发流程；按模型版本分组，不把旧版混作新版测试。记录选场规则、人工修改和未推荐样本，防止只看中奖票。
3. 总进球对照验证接入复盘UI，展示样本数、置信区间和时间窗口；先单场概率再组合收益，同时报告相关性与投注重叠。现有本轮工具只是验证基础设施，不是完成了新策略有效性证明。
4. 核验已实现的R2对象存储＋D1索引生产路径。旧历史迁移如需实施，应先复制原件并核验哈希、建立版本化清单、双读比对所有页面数量，再切换读来源；保留旧文件与回滚通道。绝不先gitignore历史再补迁移。
5. 将页面继续按数据读取、过滤、历史汇总、组合卡片、结算明细拆分；不一次性重写所有页面。为大批预测设CPU/耗时预算与队列，避免Worker一次同步计算120场。

## 本轮验收边界

新增行为测试覆盖精确拆盘、零值与空值区分、独立缓存时刻、同输入重放、温度与各玩法边际一致、旧profile隔离、半场配对分母、测试集不选AI参数、同场同投入票据对照；接口测试覆盖真实“总进球数”字段映射。历史快照目录不在本次变更中。
